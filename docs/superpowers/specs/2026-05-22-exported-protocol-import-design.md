# Импорт экспортированного протокола XLSX

## Цель

Добавить возможность открывать экспортированный протокол `.xlsx` как полноценный источник данных приложения. Такой источник должен работать так же, как исходная запись из папки с `Prova*.dat` и `Prova*.dbf`: отображаться в списке каналов, строить графики, участвовать в сравнении и смешиваться с обычными исходными записями.

Формат входного `.xlsx` всегда соответствует протоколу, который создает текущий экспорт приложения.

## Поведение пользователя

Пользователь может:

- открыть только `.xlsx` протокол;
- открыть исходную запись из `dat/dbf` и добавить к ней `.xlsx` протокол для сравнения;
- использовать существующие режимы сравнения, наложения, выбора каналов и построения графика;
- видеть каналы из `.xlsx` в общем списке каналов как каналы обычного источника.

Если в `.xlsx` и в исходной записи есть одинаковые коды каналов, существующая логика смешивания источников должна разнести пересечения так же, как для нескольких исходных записей.

## Архитектура

Импорт `.xlsx` добавляется как новый путь загрузки данных, который на выходе строит обычный `TestData`.

Основные элементы:

- новый reader в `Infrastructure/DataImport`, например `ExportedProtocolDataSourceReader`;
- загрузочный слой определяет тип источника: папка исходной записи или файл `.xlsx`;
- для папки остается текущий путь чтения `Prova*.dat`, `Canali.def` и `Prova*.dbf`;
- для `.xlsx` вызывается новый reader;
- `MergeLoadedSourcesUseCase` остается единым механизмом объединения источников.

Новый reader должен читать файл напрямую как OpenXML ZIP/XML через стандартные .NET API. Excel Interop не используется.

## Разбор XLSX

Reader читает:

- `xl/sharedStrings.xml`, если он есть;
- `xl/worksheets/sheet1.xml`;
- строку 1 для служебных данных: `B1` хладагент, `D1` исходный путь или описание;
- строку 3 для заголовков дополнительных каналов;
- строки данных начиная с 4-й.

Фиксированные каналы читаются по карте текущего шаблона:

- `D = Pc`
- `E = Pe`
- `F = T-sie`
- `G = UR-sie`
- `H = Tc`
- `I = Te`
- `J = T1`
- `K = T2`
- `L = T3`
- `M = T4`
- `N = T5`
- `O = T6`
- `P = T7`
- `Q = I`
- `R = F`
- `S = V`
- `T = W`

Дополнительные каналы читаются начиная с колонки `Z`. Если исходный короткий код канала невозможно восстановить из файла, текст заголовка используется как `Code` и `Name`. Если заголовок содержит единицу в квадратных скобках, например `unit C - Tc 8 [°C]`, единица записывается в `ChannelInfo.Unit`.

Пустые значения каналов импортируются как `null`. Некорректные числовые ячейки пропускаются как `null`, если строка в целом пригодна для импорта.

## Время

Временную шкалу нужно восстанавливать из экспортной сетки данных. В протоколе есть относительное время испытания и текущее время. Для графиков достаточно построить монотонные `TimestampsMs`.

Базовый вариант:

- использовать колонку `B` как относительное время испытания;
- интерпретировать значение Excel-даты/доли суток как дни и переводить в миллисекунды;
- если данные в `B` отсутствуют или нечисловые, использовать `C`;
- если абсолютная дата из `C` доступна и надежно читается, она может стать основой для `SourceStartMs`/`SourceEndMs`.

Импорт должен сохранять порядок и монотонность временной шкалы. Если строки в файле не отсортированы, reader сортирует их по времени так же, как DBF-reader.

## Модель TestData

Для импортированного протокола:

- `Root` равен полному пути к `.xlsx`;
- `Meta` содержит доступные служебные данные из протокола, включая хладагент и исходный путь из `D1`, если они есть;
- `Channels` содержит фиксированные и дополнительные каналы;
- `ColumnNames` содержит импортированные коды каналов;
- `Columns` содержит массивы значений;
- `TimestampsMs` содержит восстановленную временную шкалу;
- `CodeSources` указывает каждый канал на путь к `.xlsx`;
- `SourceColumns` содержит один источник с колонками этого `.xlsx`;
- `SourceStartMs` и `SourceEndMs` задаются по первой и последней валидной точке.

## Ошибки

Пользователь должен получить понятное сообщение, если:

- файл не является `.xlsx`;
- в архиве нет `xl/worksheets/sheet1.xml`;
- структура не похожа на экспортированный протокол;
- нет валидных строк данных;
- не удалось восстановить ни один канал.

Ошибки чтения одного значения не должны ронять импорт всего файла, если строка и канал могут быть представлены как пустая точка.

## Тестирование

Добавить тесты для нового reader и смешанного режима.

Минимальные проверки:

- `06.03.26 FORCE KA50 90G FULL 4040.xlsx` читается без Excel;
- импорт дает ненулевое количество строк;
- фиксированные каналы появляются с ожидаемыми кодами;
- дополнительные каналы начиная с `Z` появляются с заголовками из протокола;
- временная шкала монотонная;
- `Root`, `CodeSources`, `SourceColumns`, `SourceStartMs`, `SourceEndMs` заполнены для `.xlsx`;
- `MergeLoadedSourcesUseCase` может объединить обычный `TestData` и импортированный `.xlsx`.

Проверка сборки:

```powershell
dotnet build .\JSQViewer.csproj -c Debug
dotnet test .\JSQViewer.Tests\JSQViewer.Tests.csproj
```
