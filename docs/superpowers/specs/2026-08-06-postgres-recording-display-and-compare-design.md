# Названия прогонов PostgreSQL и добавление для сравнения — дизайн

## Цель

Исправить два связанных дефекта источников PostgreSQL:

1. Вместо пользовательского названия прогона интерфейс показывает технический источник `jsqdb://recording/<id>` или только ID.
2. Команда «Из БД…» заменяет текущую рабочую область выбранными прогонами, поэтому второй прогон нельзя добавить для сравнения с уже открытым источником.

Технический URI остаётся стабильным идентификатором источника. Пользовательское название хранится отдельно и применяется только для отображения.

## Подтверждённое поведение

- «Из БД…» добавляет выбранные записи к уже открытым источникам.
- Общий лимит рабочей области остаётся равным шести источникам независимо от их типа.
- Повторно выбранный источник не добавляется.
- При заполненной рабочей области приложение сообщает о лимите и ничего не очищает.
- Для прогона PostgreSQL отображается его поле `Название`; при пустом названии используется ID записи.
- Для папок и экспортированных протоколов сохраняется существующее отображение имени файла или папки.
- Дружественные имена применяются в заголовке графика, заголовках окон каналов и префиксах каналов при сравнении.
- Для нескольких источников заголовок графика перечисляет их имена через `;`.
- Live-refresh продолжает работать по техническому URI и не зависит от отображаемого имени.

## Корневые причины

`MainForm.OpenFromDatabaseButtonOnClick` рассчитывает свободное количество источников с учётом текущего workspace, но после закрытия диалога создаёт новый список только из `SelectedSources`. Текущие источники отбрасываются.

Заголовки и подписи строятся непосредственно из `IViewerSession.Folder`, `TestData.Root` или `Path.GetFileName(sourceRoot)`. Для `jsqdb://recording/<id>` это технический URI/ID. Название уже читается из PostgreSQL в `TestData.Meta["Название"]`, но после объединения нескольких источников нет отдельной связи «источник → отображаемое имя».

## Модель данных

В `TestData` добавляется словарь:

```csharp
Dictionary<string, string> SourceDisplayNames
```

Ключ — канонический source root (`jsqdb://recording/<id>`, путь к папке или `.xlsx`). Значение — дружественное имя.

Инварианты:

- словарь всегда не `null`;
- сравнение ключей регистронезависимое;
- для каждого источника в `SourceColumns` допускается отсутствие записи, но UI обязан использовать безопасный fallback;
- технические структуры `Root`, `SourceColumns`, `CodeSources`, `SourceStartMs` и `SourceEndMs` не заменяются дружественными именами.

## Формирование отображаемого имени

Единый resolver применяет правила в таком порядке:

1. Непустое значение `SourceDisplayNames[sourceRoot]`.
2. Для одиночного источника — непустое `Meta["Название"]`.
3. Для `jsqdb://recording/<id>` — ID записи.
4. Для файлового источника — существующий `Path.GetFileName` после удаления завершающих разделителей.
5. Исходная строка source root.

`PostgresRecordingDataSourceReader`/`RecordingRowsToTestDataMapper` записывает название из метаданных в `SourceDisplayNames`. `AppendNewWindows` сохраняет существующий словарь без изменения.

Файловые читатели не обязаны заполнять словарь: resolver сохраняет прежнее поведение через fallback.

## Объединение и удаление источников

`MergeLoadedSourcesUseCase` объединяет `SourceDisplayNames` всех входных `TestData` по тем же каноническим root, которые используются в `SourceColumns`.

`RemoveLoadedSourceUseCase` удаляет имя закрытого источника и сохраняет имена оставшихся источников.

Все операции продолжают использовать source root как идентификатор; одинаковые названия разных прогонов допустимы и не приводят к конфликту.

## Добавление записей из БД

Объединение списков источников оформляется как тестируемая операция прикладного/оркестрационного слоя, а не как неявная манипуляция внутри event handler:

1. Разобрать текущий `FolderSpec`.
2. Добавить выбранные URI в порядке выбора.
3. Удалить дубликаты с `StringComparer.OrdinalIgnoreCase`, сохранив первое вхождение.
4. Проверить общий лимит `WorkspaceFolderSpecParser.MaxFolderCount`.
5. Если новых источников нет, показать сообщение о дубликате и не перезагружать workspace.
6. При успехе сформировать новый `FolderSpec` и вызвать существующий `LoadFolder`.

Если текущая рабочая область уже содержит шесть источников, диалог выбора не открывается и приложение показывает существующее сообщение о лимите. Текущий workspace никогда не очищается автоматически.

## Использование в UI

Один resolver дружественных имён используется в следующих местах:

- заголовок основного окна графика;
- заголовок отделённого графика;
- заголовки окон каналов;
- префиксы каналов/ролей прогноза при нескольких источниках;
- обновление подписей при смене языка.

Для одиночного источника заголовок графика содержит одно дружественное имя. Для нескольких — имена в порядке `SourceColumns`, разделённые `; `. Пустые и повторяющиеся подписи не выводятся; если определить ни одно имя нельзя, используется текущий `IViewerSession.Folder`.

## Ошибки и совместимость

- Ошибка загрузки добавленного прогона обрабатывается существующим rollback в `LoadFolder`; прежняя рабочая область и live-refresh сохраняются.
- Отображаемое имя не участвует в запросах PostgreSQL, recent sources, workspace key и live-refresh.
- Старые `TestData`, тестовые fixtures и файловые источники совместимы благодаря инициализации словаря и fallback-правилам.
- JSON-форматы настроек и сохранённых layout не меняются.

## Тестирование

Автоматические регрессии должны подтвердить:

- текущие источники и выбранные записи БД объединяются в правильном порядке;
- дубликаты не добавляются;
- лимит шести источников не позволяет очистить или заменить workspace;
- mapper создаёт имя записи из `Meta["Название"]` и использует ID при пустом названии;
- merge сохраняет отдельные имена двух записей;
- remove удаляет только имя закрытого источника;
- append сохраняет имя активной записи;
- resolver корректно обрабатывает DB, папки, несколько источников и fallback;
- UI заголовки используют resolver, а не технический URI.

Ручная проверка:

1. Открыть запись из БД — заголовки графика и каналов содержат название, не ID.
2. Снова нажать «Из БД…», выбрать другую запись — обе записи остаются в workspace и доступны для сравнения.
3. Проверить одинаковые коды каналов: префиксы различают источники по названиям.
4. Повторно выбрать уже открытую запись — дубликат не появляется.
5. Заполнить workspace до шести источников — следующий источник не добавляется, текущие данные остаются.
6. Для активной записи дождаться live-refresh — название и идентификатор источника не меняются.

## Не входит в изменение

- Изменение формата `jsqdb://recording/<id>`.
- Снятие лимита в шесть источников.
- Переименование записей в базе данных.
- Сохранение локальных пользовательских псевдонимов.
- Изменение SQL-каталога или алгоритма live-refresh, кроме передачи нового display-name поля через существующие данные.
